# Deviations

Changes made after the pre-registration tag are recorded here with their date and rationale (pre-registration, Deviation rule). The labeling-branch switch is recorded here as §4 requires, although it is made before the tag.

| Date | Change | Rule that allows it | Rationale |
|---|---|---|---|
| 2026-11-14 | Labeling of the 54 hand-written cases moves from Branch A (two raters) to Branch B (one rater: the author labels every case and re-labels it after at least 48 hours without access to the first-pass labels; intra-rater kappa on per-item eligibility with its case bootstrap 95% CI; the subset earns the name Self-verified only when kappa is at least 0.70, an undefined kappa earns neither name, and it is never Verified; the gate is pinned by decision D-R19, 2026-11-14) | §4 Labeling protocol: Branch B is the pre-registered fallback when the external reviewer is not named and committed at the tag; decision D-R18 | No external reviewer is named at the tag. The switch is made before any label comparison, before the dataset freeze and before any evaluation-split run |
| 2026-11-14 | Tooling item (1), the evaluation-split path of the review packet, freeze and run report. `scripts/review_packet.py` accepts an evaluation-split log only when its task arguments hold `allow_evaluation_split` true, refuses a packet that mixes splits and refuses an evaluation-split log that does not hold the 200 cases (146 synthetic, 30 edge, 24 adversarial). An errored or unscored epoch is carried as a failed trial with no finding unit and is listed in the sealed summary; when it still holds an FM code, its audit rows and its whole-narrative read are kept as for any FM-coded epoch. `icfr_agent_evals/trials.py` checks the carried list against the log, and a code with no audit row on a carried epoch is counted as not audited, never as `real_error`. `scripts/review_freeze.py` checks the second-look freeze commit (manifest alone, reviewer trailer, after the first freeze, draw at least 48 hours after it, blinding check present on a full run) and refuses the expanded CSV on the evaluation split. The new `scripts/run_report.py` computes no review-settled or audit-adjusted figure until both freeze checks pass; until then it prints counts only, with no model name or per-model figure, on the evaluation split. It reads the reasoning mode from the logged model calls | §13, row "Tooling built after the tag and before the first evaluation-split run", item (1) (decision D-R19); §6, §8 and §9 | Planned tooling, not a rule change. The code carries out rules fixed in the tagged text; no rule, threshold or criterion changes. Built with unit tests on mock logs; no evaluation-split case is built, read or scored |
| 2026-11-14 | Tooling item (2), the grader call with its pinned configuration. `icfr_agent_evals/grader.py` makes every grader call with `roster.grader_generate_config_args` (reasoning effort high, temperature unset, the Batch API at ladder steps 2 and 3) and response caching off, and checks a grader log against the pin and the resolved model string recorded at the tag. `scripts/grader_live_check.py` holds the first live check; it makes no call unless `--live` is given and has not been run | §13, row "Tooling built after the tag and before the first evaluation-split run", item (2); §5; decision D-R12 | Planned tooling, not a rule change. The live check needs the author's keys and runs before any evaluation-split run |
| 2026-11-14 | Tooling item (3), the judge-trust statistics. `icfr_agent_evals/judge_trust.py`: ICC(A,1) with its McGraw-Wong 95% interval, ICC(C,1) with its exact F interval, ordinal Krippendorff's alpha with a unit-bootstrap 95% interval, q and raw agreement (an undefined alpha is reported as undefined and fails the test-retest gate), the exactly-3-pass test-retest runner (the acceptance-look scoring is pass 1, caching off, each pass checked against the grader pin), the bias-audit passes with the largest pairwise test-retest baseline and the 0.10 and 0.25 limits, and the per-run reliability exclusion outside the judge remedy order | §13, row "Tooling built after the tag and before the first evaluation-split run", item (3); §7 | Planned tooling, not a rule change |
| 2026-11-14 | Tooling item (4), the second-look scorer. In `scripts/review_freeze.py` a worker run with no second-look units gets the result "second look empty", never "confirmed"; the result gives the count of narrative-only units of the 54 difficulty-bearing cases first ruled whole-narrative `wrong`, labeled not second-looked; and the scorer refuses any bootstrap seed other than the one derived from the frozen first manifest, or derives it | §13, row "Tooling built after the tag and before the first evaluation-split run", item (4); §8 | Planned tooling, not a rule change. At the tag a run with no second-look units fell through to the branch that reads "confirmed"; the text says such a run is never confirmed |
| 2026-11-14 | Tooling item (5), the blinding-check pool. `scripts/review_freeze.py` judges uniqueness on the narrative text the reviewer is shown, for the same case: a text counts only when exactly one worker run holds it, and no text is shown twice. When fewer than 40 texts qualify, all are drawn | §13, row "Tooling built after the tag and before the first evaluation-split run", item (5); §8; decision D-R6 | Planned tooling, not a rule change |
| 2026-11-14 | Tooling item (6), the Branch B labeling kappa. The new `scripts/labeling_kappa.py` reads the two exports of `scripts/labeling_sheet.py` and computes unweighted Cohen's kappa between the two passes on per-item eligibility, items matched by reference and an omitted item counted as not eligible, with a 10,000-resample case bootstrap 95% interval whose undefined resamples are dropped and counted, under the seed recorded with the dataset version. The name Self-verified is given only at a point estimate of at least 0.70, never Verified; an undefined kappa earns neither name. No name is given when the passes do not cover the 54 cases or the timer data shows a re-label less than 48 hours after the first pass. Direction, band and evidence-state kappas and the $1 amount-match share are reported beside it | §13, row "Tooling built after the tag and before the first evaluation-split run", item (6); §4 Branch B; decisions D-R18 and D-R19 | Planned tooling, not a rule change. The statistic is labeled intra-rater (test-retest) kappa |
| 2026-11-14 | Tooling item (7), the H3 computation. `icfr_agent_evals/h3.py` tests the twelve paired steps (Haiku 5.5 at most Sonnet 5, Sonnet 5 at most Sonnet 5.5, Sonnet 5 at most Opus 5.5, on correctness, fabrication, reconciling items and completeness) over the 54 difficulty-bearing cases pooled. A step holds when the mean per-case difference of epoch means is at least 0, and H3 holds only when all twelve hold, failing steps named. Each difference gets a paired 95% t interval with 53 degrees of freedom, outside the verdict. H3 is reported as not tested when any worker's second look is not confirmed, and is tested under the label when a second look is empty. The reasoning mode is printed beside every delta | §13, row "Tooling built after the tag and before the first evaluation-split run", item (7); §2 H3; decision D-R19 | Planned tooling, not a rule change. Reported H3 comes only from `scripts/run_report.py`, after both freeze checks |
