Windows truststore note. On Windows, the anthropic 1.12.1 and openai 3.27.0 SDKs use httpx2, and httpcore2 builds its default TLS context with `truststore.SSLContext`. truststore runs the OpenSSL handshake with `CERT_NONE` and then checks the chain through Windows CryptoAPI. CPython's eMudhra denylist applies only when verification is on (`CERT_OPTIONAL` or `CERT_REQUIRED`), so it probably does not fire on this path. Protection for the API calls on Windows rests on Microsoft's Disallowed Certificate Trust List update of 2026-10-20 and the out-of-band root removal of 2026-10-26. On Linux, and on Windows when `SSL_CERT_FILE` or `SSL_CERT_DIR` is set, httpcore2 uses a stdlib ssl context with `CERT_REQUIRED`, so the denylist does fire. The stdlib default context on Windows does not read the Disallowed store, so a dependency that uses stdlib ssl gets the denylist only from 3.14.10. (Measured: `httpcore2/_ssl.py`, `truststore/_windows.py`, `truststore/_api.py` in the pinned venv. Sourced: https://github.com/python/cpython/issues/160040 ; https://www.microsoft.com/en-us/msrc/blog/2026/10/microsoft-response-to-compromised-emudhra-certificate-authority-keys . ## Serving guard

Decision: before any sample runs, the roster check resolves each bound real model's client endpoint and fails unless it is exactly `https://api.anthropic.com` (anthropic) or `https://api.openai.com/v1` (openai), with one trailing slash ignored. The Scout scan jobs apply the same check to the scanner model. Offline mockllm runs are unaffected.

Paths a base URL or a substitute credential can arrive by in inspect-ai 0.3.278 (measured in the pinned source and with offline `get_model` probes, no request sent):

| Path | Effect |
|---|---|
| `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL` (shell or `.env`) | Reroutes that provider's client. `str(model)` is unchanged and `api.base_url` stays None, so only the client URL shows it |
| `INSPECT_EVAL_MODEL_BASE_URL` | Reroutes both the Anthropic and the OpenAI client |
| A blank value of any of the three | Leaves a client URL of `''`, so requests fail rather than reroute |
| `--model-base-url`, `eval(model_base_url=...)`, `get_model(base_url=...)` | Sets an explicit base URL; `str(model)` is unchanged |
| `--model-spec` with a `base_url` field (also from `INSPECT_EVAL_MODEL_SPEC`) | Sets an explicit base URL for the evaluated model |
| A role spec with `model_args: {base_url: ...}` (`--model-role`, or `INSPECT_EVAL_MODEL_ROLE`) | Sets both `explicit_base_url` and `api.base_url` to the proxy while the name stays on its pin |
| `-M base_url=...` for the main model | Raises a TypeError, so it fails loudly |
| Other `model_args` such as `profile` | Can reach the SDK's profile and credentials-file base URL chain |
| `SCOUT_SCAN_MODEL_BASE_URL` (scout scan) and `INSPECT_EVAL_SCAN_MODEL_BASE_URL` (inline scans) | Set the scan's default model base URL. The vendored llm scanners name their model and resolve it without that base URL (measured), so these do not reach them; the scan jobs refuse them anyway as a precaution |
| `ANTHROPIC_AUTH_TOKEN` | Leaves the host alone, but Inspect then authenticates with it instead of `ANTHROPIC_API_KEY`, and the log does not say so |
| `ANTHROPIC_CUSTOM_HEADERS` (shell or `.env`) | Leaves the host alone, but the anthropic SDK merges these headers after its auth headers, so an `X-Api-Key` or `Authorization` header here replaces the request credential. The log does not say so |
| `OPENAI_CUSTOM_HEADERS` (shell or `.env`) | The same for the openai SDK: an `Authorization` header here replaces the request credential while the host stays first-party |

Inspect loads the first `.env` found walking up from the working directory on every CLI command, `eval()`, `eval_set()` and `inspect view`; Scout loads one too. The SDKs fall back to `ANTHROPIC_BASE_URL` or `OPENAI_BASE_URL` themselves when Inspect passes no base URL. (Measured: `inspect_ai/_util/dotenv.py`, `inspect_scout/_scan.py`, `anthropic/_client.py`, `openai/_client.py`.)

What the EvalLog records and does not (measured: `inspect_ai/_eval/task/log.py`, `inspect_ai/model/_model_config.py`, `inspect_ai/log/_log.py`):

- `EvalSpec.model_base_url` holds the evaluated model's explicit base URL only.
- Each role's `ModelConfig.base_url` holds that role's `api.base_url` only.
- `ModelCall` has no URL field.
- So a base URL set by an environment variable leaves no trace in the log. Retry and score reuse the logged values, so an environment route still set at that time is picked up again.

What the guard checks (measured: `icfr_agent_evals/roster.py`, `icfr_agent_evals/scanners/_model.py`, `icfr_agent_evals/scanners/jobs.py`):

| Check | Result |
|---|---|
| Allowed endpoints | `roster.FIRST_PARTY_BASE_URLS`: anthropic `https://api.anthropic.com`, openai `https://api.openai.com/v1`. Compared exactly after stripping one trailing slash, so `https://api.anthropic.com//` fails |
| Roles bound to a list | A role bound to more than one model fails the roster check before any role is resolved. Inspect would otherwise check only the first model in the list, for both the roster names and the endpoint |
| Order in `roster_check` | `validate_roster` (names, pins, roles, the mockllm rule) runs first and is unchanged. On a run that is not offline, the guard then runs on the evaluated model and both roles |
| Order in `validate_serving` | Provider, auth token, custom headers, `model_args`, explicit base URL, client URL type, blank, exact match |
| Fails on | An unknown provider; a non-empty `ANTHROPIC_AUTH_TOKEN` for an anthropic model (a blank one passes, since Inspect ignores it); a non-blank `ANTHROPIC_CUSTOM_HEADERS` or `OPENAI_CUSTOM_HEADERS`, since either can replace the request credential while the host stays first-party; any `model_args` at all, because no roster run uses them; an explicit base URL other than the allowed one (both `explicit_base_url` and `api.base_url` are read); a blank client URL; any other client URL |
| Fails closed | An unreadable client, or a URL object that is not an httpx2 or httpx URL, is refused. The pinned SDKs expose `client.base_url` as `httpx2.URL` |
| Transcript record | On a real run, once per sample in the setup step, an info event with source `roster_check` and data `{"serving_endpoints": {"evaluated_model": {...}, "grader": {...}, "calibrator": {...}}}`, each entry holding `model` and `base_url` as read (OpenAI keeps its trailing slash). Offline runs record nothing |
| Scan jobs | Each scan job first loads the project `.env` the way Scout does (Scout's own loader, which honours `PYTHON_DOTENV_DISABLED`), so the check sees the environment the scan and its workers use. `scanner_job_serving` then reads the built ScanJob's model and `model_base_url`. It refuses a `model_base_url` that is not None, a non-empty `SCOUT_SCAN_MODEL_BASE_URL` or `INSPECT_EVAL_SCAN_MODEL_BASE_URL`, and a resolved model that is not the scanner model, then applies the same endpoint check. The job metadata gains `scanner_endpoint` (None on mockllm) |
| Tests | `tests/test_serving_guard.py`, 102 test cases, mock only: `get_model(..., api_key="test", memoize=False)` and no generate call, with the home and config folders pointed at a temporary path. Passed on 2026-11-05 on 3.14.10 and 3.12.16 within the full keyless suite |

Limits (inferred). The scan-job check reads the environment when the job is built; the llm scanners resolve the scanner model by name again when they run, so a variable changed in between is not seen. The scan jobs load the project `.env` the way Scout does before the check, so the check sees the environment the scan and its workers use. On a non-Windows host, Scout's spawn workers re-resolve the scanner by name; they are covered only because the job loads `.env` before the check, and a variable set in a worker by other means is not seen. Run the scanners only through the package's scan jobs: running a scanner file directly (`scout scan <scanner>.py`, `inspect eval --scanner`, `INSPECT_EVAL_SCANNER`) builds no scan job and skips both the split guard and the serving guard. Never pass `--metadata` or `scan(metadata=...)`: either replaces the job metadata, the endpoint record included. A scan-level `-M` reaches only the scan's default model, which the llm scanners do not use. `HTTPS_PROXY`, `HTTP_PROXY` and `ALL_PROXY` change the network path, not the base URL; TLS still ends at the vendor unless a custom CA bundle is installed, so they are outside a base-URL guard.

Since the guard fails closed, the fixed `roster.SERVING_PLATFORMS` claim of first-party serving in the run config is true by construction for any run that scores a sample.

## Dataset SemVer

Decision: the post-tag dataset build is version 0.1.0. `DATASET_VERSION` stays 0.1.0-dev.1 through the tag and is set to 0.1.0 at the post-tag freeze, with the 54 hand-written cases, before the first CI baseline. After the 0.1.0 freeze, any change to the cases or the schema creates a new dataset version, raising the minor number while the major number is 0.
