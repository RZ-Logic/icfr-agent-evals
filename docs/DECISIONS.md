## 1. What the score of record is

- **The score that counts is the review-settled one.** Code flags, the author settles the flags, and per-epoch failure codes stay final. The audit-adjusted figure is shown beside it as a sensitivity check only. [D-A, 2026-11-09]
- **The route-blind figure is an upper bound,** and PR CI's McNemar test reads it. A third sign-off rule, R3, is pre-registered now. [D-E5, 2026-11-10]
- **A parse failure (FM-000) is never removed** by the code audit. The audit-adjusted figure keeps it whatever the audit rules. [D-R5, 2026-11-10]
- **Frozen verdicts stay of record.** If anything is amended later, the amended figures are shown beside the frozen ones, labelled amended. [D-M, 2026-11-10]
- **H2 counts only the code-caught failures** that the code audit rules a real error. [D-N, 2026-11-10]
- **FM-000 supports H2 only when the code audit rules it a real error,** like every H2 code; D-R5 keeps FM-000 in the audit-adjusted figure only. [D-R15, 2026-11-13]
- **H3's step rule:** H3 is tested on the 54 difficulty-bearing cases pooled, on four anchors (correctness, fabrication, reconciling items, completeness) and three steps (Haiku 5.5 ≤ Sonnet 5, Sonnet 5 ≤ Sonnet 5.5, Sonnet 5 ≤ Opus 5.5), and holds only when all twelve steps hold. A step holds when the mean per-case paired difference is at or above 0; its paired 95% t interval is reported and does not enter the verdict. H3 is not robust if the two orderings disagree, and not tested if a second look fails. [D-L, 2026-11-10; D-R19, 2026-11-14]

## 2. Citation omissions (naming a case-file entity but leaving it out of the structured citations)

- **A citation omission no longer fails a trial.** It is still detected and counted, and reported as its own measure, citation-pass^4, beside the score of record. Changed after the pilot, because of it, and disclosed. [D-R9, 2026-11-11]
- **CI still guards it:** its own per-case McNemar test (alpha 0.025, outside the Holm family) plus a sign-off case on a rise, kept out of the review volume that sets the ladder rung. [D-R9, 2026-11-11]
- **A reviewer's citation_omission verdict passes only if code confirms the name really is in the case file,** so a made-up name can never pass that way. [D-R9, 2026-11-11]
- **A reviewer's citation_omission verdict is counted apart as review-found.** It never enters citation-pass^4, which code computes from the log alone. [D-R19, 2026-11-14]
- **A reference in reconciling_items counts as cited,** like an entry of entities_cited, so naming it in the narrative is not an omission. An uncited organization, person, address or hash the case file holds exactly is counted as an omission by code, with no review needed. [D-R19, 2026-11-14]
- **Every epoch with an omission the P12 rule finds gets a whole-narrative read,** so none passes unread. An uncited organization, person, address or hash keeps its review route and is read that way; a mention only the wallet-label matcher finds is counted but adds no read. [D-R9, 2026-11-11]
- **Wallet labels are matched directly** (ignoring case, spaces and hyphens), so a missed citation of a wallet is counted. This only adds catches. [D-R9, 2026-11-11]
- Background: P12 (2026-11-07) made an uncited case-file reference or wallet label a citation omission; D-R9 keeps the detection and changes only its effect.

## 13. After the tag

D-R20 (2026-11-15) is the first ruling after the tag. It settles points the tagged text leaves open for the tooling built after the tag, and changes no rule, threshold or criterion of the pre-registration. It is logged in DEVIATIONS.md.

- **An errored epoch is a format break (FM-000):** an epoch that ended in an error fails its trial, scores 0 on every anchor, and counts as FM-000 in every FM count, the format-break rate and the CI regression gates. It gets its FM-000 code audit and its whole-narrative read, stays in the audit-adjusted figure, and supports H2 only when the audit rules it `real_error`. The audit sees the error's class name, never its message. An epoch with a missing score and no error stays a failed trial. This follows §9: a missing or refused generation stays a format break. [D-R20, 2026-11-15]
- **The sensitivity row drops only the defect epochs:** an epoch hit by an extractor crash or an answer-key mismatch leaves the row; a case passes when all its remaining epochs pass; a case with every epoch dropped leaves the row; the count of cases scored on fewer than four epochs is given per model and subset. The row is given for all three figures, never as the score of record, and an errored epoch is never dropped from it. [D-R20, 2026-11-15]
- **Blinding check pool:** a text that another worker run also wrote, on any case, leaves the pool, since it has no single right answer; an empty text never enters it. [D-R20, 2026-11-15]
- **H3 robustness** compares the set of failing steps across the readings, and a gap of exactly one standard error counts as saturation. [D-R20, 2026-11-15]
- **An undefined reliability limit fails:** when the full-run ICC(A,1) lower limit cannot be computed, that sub-dimension is excluded for the run and the other is decided on its own value. [D-R20, 2026-11-15]
- **Test-retest and bias-audit details are kept as built:** the alpha bootstrap uses 10,000 unit resamples with undefined resamples dropped and counted, and the one seeded option permutation is kept, and flagged, when it comes out as the identity or the reversal. [D-R20, 2026-11-15]
- **Labeling checks:** the 48-hour gap is shown on every case from the sheet's timer, or the subset gets no name; the published adjudicated-case count is the count of cases differing on any label, a label given in one pass and left blank in the other counting as differing. [D-R20, 2026-11-15]
- **The template baseline goes in the review packet,** so its reference row gets all three figures; an evaluation-split packet without it is refused. [D-R20, 2026-11-15]
- **Grader development rounds (D-R21):** in step 1 of the judge remedy order, the first grading of the judge-development set with the first prompt wording is round 0 and targets no pattern; at most 3 rounds follow, each after an edit for a named disagreement pattern, so the 3-round cap counts edits. [D-R21, 2026-11-17]

- **The acceptance look (D-R22):** a look that stops part-way is resumed: finished passes are kept, only the unfinished ones run, and every attempt and failure is listed in the look file; it is still one look. A grader reply that cannot be read is never asked again: every gate that needs the missing score is reported FAIL with the reason, and the other gates are computed as usual. Section 7's point-biserial correlation for partial-credit items is not applicable in Phase 1: the rubric defines no binary check and no partial-credit item. [D-R22, 2026-11-17]

- **The full-run grading job (D-R23):** the grader of record grades every gradeable generation of the evaluation run, a calibrator grades a drawn sample of them, and the job follows the named items below, which the code cites by name. Ruled on 2026-11-22 and amended on 2026-11-23, before any grader or calibrator output existed. [D-R23, 2026-11-22, amended 2026-11-23]
  - **grader of record:** GPT-6.1 Terra at ladder step 2 on the OpenAI Batch API, with prompt gp-1 at its default settings, reasoning effort high and response caching off, because the step 2 acceptance look passed. The job runs from scripts, not as a package job, so the package stays as it was at the run commit and the section 8 package-hash rule is met.
  - **units:** the grader grades every generation whose worker output parsed and did not error, in all four worker runs, Opus 5.5 included. Unparsed and errored epochs are counted and never graded. An errored epoch whose completion happens to parse is still skipped (D-R20). The template baseline is not graded, so the cost row counts the 3,200 worker generations only. The separate Scout scan counts inside the same full-run total.
  - **draw:** the calibrator sample is drawn by case rotation before any grader output exists. Every seed of the job is fixed by rule: the first 16 hex digits, read as an integer, of the SHA-256 of the four worker-log SHA-256s sorted by model id and joined with "|", followed by a suffix that names its use. The draw uses the suffix "|calibrator". The 200 case ids, sorted, are shuffled once. The three non-Opus worker runs, sorted by id, take positions 1 to 80, 81 to 160, and 161 to 200 then 1 to 40. For each (run, case) one gradeable epoch is picked at random with the same generator. A (run, case) with no gradeable epoch loses its row, with no refill, so n is 240 or slightly fewer. A non-Opus generation's chance of selection is 0.4 divided by its number of gradeable epochs. The draw refuses when the calibrator's own model is not among the worker runs.
  - **calibrator:** Opus 5.5 at effort high, with response caching off, not batched, and with no fallback model, no tools and no sampling field. A forbidden request field sent empty carries no value and passes the log check; the pinned Inspect sends an empty tools list on every call. The code calls generate once. Inspect's own retries of transient errors apply, and the log check skips each errored attempt. All calibrator calls must send one reasoning mode and resolve to one model string, a string the Opus 5.5 worker log also resolved to; anything else is a vendor-change event. The calibrator reads gp-1 unchanged, so it grades what the grader graded under the same prompt hash. If the plumbing check fails, a scripts-only remedy may replace this, and the same-hash claim is then dropped and disclosed. A refusal is logged as a refusal. There is no calibrator acceptance look, because the pre-registration gives looks to graders only.
  - **plumbing check:** before any evaluation-split calibrator call, a dev-only check runs gp-1 through the calibrator on 12 judge-development outputs, not batched, and the calibrator log check reads its log. Per reply it reports only whether the reply parsed, whether it was refused, token use, and for a reply that does not parse a fixed failure category: not one JSON object, wrong keys, label not offered, flag not boolean, refused, no call, or does not parse. It never prints or stores the parser's text or a grade, so it is not a look. Its fail branch is fixed now: if any reply does not parse, the evaluation-split calibrator run does not start, the author picks a scripts-only remedy as a logged deviation, and the check is rerun on the same outputs. A passed check counts only while `scripts/calibrator_call.py`, `scripts/grading_common.py`, `scripts/calibrator_plumbing_check.py` and the package are unchanged since its commit. When any of them changes, the check runs again as the next numbered attempt on the same outputs; at unchanged code a passed check is not run again. The job also checks that the check's log carries the check's task name and the dev split, and that its calls resolved to the Opus 5.5 worker log's model string. The job asks no part, grader parts included, until the check has passed.
  - **failed judgments:** a judge reply that does not parse and a refusal are never asked again and never refilled. A refusal is a refusal stop reason, refusal content or refusal stop details. A unit asked in two attempt logs with no completed call is next asked in an isolated eval, which holds only units at their third ask and runs one sample at a time, so one failing request cannot fail another. A unit asked in three attempt logs with no completed call, one of them isolated, is a failed judgment with no reply. It is never asked again, it goes to the queue, it is counted as failed in the pooled counts, and it is treated exactly as a reply that does not parse: for the grader it is ungraded, and for the calibrator its pair is dropped. A unit counts as asked in a log only when that log holds its sample with a judge call, so an eval cut off before its samples reached the judge asks nothing. An outage of the whole account, such as a budget cap, a spend limit, a key error or the provider down, fails every call. When an eval ends with units left and some units of that part are now due for their final ask, the job prints a warning: the next resume asks them one at a time and records any with no reply as a failed judgment, so the cause of the first error should be found first. Before an isolated eval, a final ask guard stops the job with exit 3 when more than 12 units of the part are due, or when the role's most recent attempt log that sent at least one unit completed no call and sent more units than are now due, so that a whole eval failed. The guard makes no call, records nothing as a failed judgment, and records its stop as a failure. A single unit asked alone that completed nothing still reaches its isolated eval with no flag. The way past the guard is a resume with --allow-final-ask, valid only with --live --resume. The author passes it only after finding the cause and logging a deviation. Each resume records in the ledger whether the flag was passed.
  - **reliability gate:** the gate is the one the tagged pre-registration states. A sub-dimension passes when, and only when, the lower limit of the McGraw-Wong 95% interval of grader-versus-calibrator ICC(A,1) on complete pairs is at least 0.60; the point estimate is given beside it. A complete pair is a drawn row where both replies parsed. A pair where either reply did not parse, a refusal or a failed judgment included, is a dropped pair. An undefined lower limit fails (D-R20), and fewer than 2 complete pairs exclude every sub-dimension as undefined. A sub-dimension that fails is excluded from every claim of the full run, and the anchors stand alone. Three more figures are sealed beside the gate, each labelled reported, not gated. The first is a worst-case figure that puts each dropped pair back at its largest possible disagreement. When one reply parsed with score s, the missing score is 0 for s of 2 or 3 and 3 for s of 0 or 1. When neither parsed, the pair is 0 against 3, the grader taking 0 on the first such row in unit-id order and the direction alternating after that. Only its icc_a1 is meaningful; every other value in it is computed on filled scores. The second is the break-even count per sub-dimension: the fewest added dropped pairs, each 0 against 3 with the direction alternating, that bring the complete-pairs lower limit below 0.60 or make it undefined. It is 0 for a sub-dimension already excluded, and the search stops at the number of complete pairs. The third is a case-cluster percentile bootstrap lower limit on complete pairs: 10,000 resamples of cases with all their rows, seed suffix "|bootstrap", undefined resamples dropped and counted. A row lost in the draw is not a dropped pair and gets no fill. Rows that share a case are not independent. At the ceiling, high raw agreement can still fail: for example, a 240-row matrix with 97.5 percent exact agreement (228 pairs at 3 and 3, 6 at 2 and 2, and 6 one point apart, 3 each way) gives 0.655 with a lower limit of 0.576. An all-equal sub-dimension is undefined and is excluded under D-R20. The two-figure gate approved on 2026-11-22, which kept a sub-dimension only when the complete-pairs and the worst-case lower limits both reached 0.60, is withdrawn on 2026-11-23, before any output exists. It changed a gate criterion after the tag, which the deviation rule allows only with a new tagged version.
  - **queue:** a generation is tagged for the queue when grader and calibrator differ by more than 1 point on a sub-dimension, when either flags low confidence, or when either judge's reply did not parse, a failed judgment included. Each item carries empty disposition fields and no model id. A reply that did not parse keeps its raw reply and its error in the item. When both judges parsed, the item offers the four dispositions of section 7: grader-correct, calibrator-correct, both-wrong and ambiguous-edge-case-add-to-Verified-subset. When the grader reply did not parse and a calibrator score exists, it offers calibrator-correct, both-wrong and ambiguous-edge-case-add-to-Verified-subset. With no calibrator score (a unit outside the calibrator sample, or a calibrator reply that did not parse) and a parsed grader reply, it offers grader-correct, grader-wrong and ambiguous-edge-case-add-to-Verified-subset. With no calibrator score and a grader reply that did not parse, a refusal or a failed judgment included, it offers only grader-wrong and ambiguous-edge-case-add-to-Verified-subset, since there is no grader score to be correct. The value grader-wrong is new beside the four of section 7. Grader scores are of record: no disposition changes a grade, a mean, the reliability gate or a breaker rate, and dispositions are reported only as counts per value and as the resolution rate. Queue dispositions go in a sibling of the packet folder, never inside it, with their own SHA-256 and rows keyed by unit id.
  - **circuit breaker:** its unit is the full run, the unit of the reliability gate. It has two rates. The pair rate is the tagged complete pairs over the complete pairs of the calibrator sample. The generation rate is the tagged generations over the generations with a parsed grader reply, pooled across the four worker runs, Opus 5.5 included. A generation is tagged for the breaker when its grader reply parsed and flags low confidence, or when its pair is complete and the judges differ by more than 1 point or the calibrator flags low confidence. A reply that did not parse, a refusal or a failed judgment included, is never a breaker tag by itself. A dropped pair leaves the pair rate, and its generation stays in the generation rate on its grader reply alone. The breaker trips when either rate is above 25 percent, compared exactly. An undefined rate, one with no denominator, does not trip. A trip excludes both LLM sub-dimensions from every claim of the run, and the anchors stand alone. Per-worker rates are computed but are descriptive only and never trip.
  - **means:** the LLM sub-dimensions are reported as two means per worker run, subset and sub-dimension. The primary mean is over graded generations and is labelled conditional on a parsed worker output. The sensitivity mean is over all generations, with worker format breaks, errored epochs included, counted as 0. A grader reply that did not parse, a failed judgment included, stays missing in both and is counted. The point estimate is the mean of per-sample epoch means: a sample's epoch mean is over its graded epochs, and every sample counts once. The 95% interval is normal, from the standard error of the per-sample epoch means, and is clipped to the 0 to 3 scale; each block says so. The number of samples scored on fewer than four epochs is given per run and subset, and the D-R20 defect-epoch row is given for both means. Paired differences between runs use the samples with a value for both models and are labelled by reading, primary or sensitivity. No composed dimension score is computed: the two LLM sub-dimensions are reported on their own beside the anchors and never combined with an anchor score, because section 6 promises a composed score but fixes no weights, and no hypothesis, gate or threshold reads one.
  - **grading order:** grading runs in one pooled order, not one eval per worker run. Every gradeable unit, sorted by model, sample id and epoch, is shuffled once with the seed suffix "|grader-order", and its opaque id is its position in that order. The grader evals take the ids in four parts of roughly equal size by position. The calibrator asks the drawn ids, sorted, in an order shuffled with the suffix "|calibrator-order". No eval name, task argument, metadata field, sample id or ledger key names a worker run. Every eval runs with continue_on_fail, so one failed sample does not end the eval. The option --grader-max-samples (default 200) sets the most grader requests in flight in one eval. It is recorded in each attempt and each attempt log, and a resume may use another value. An isolated eval runs one sample at a time, and the calibrator eval uses Inspect's default.
  - **sealed folder:** the job may run before the review packet and the second-look freeze, because what it prints and commits is counts pooled over all logs together. Everything else goes to a sealed folder outside the repository, named `_sealed`: the per-record grades and reasons, the queue, every score aggregate, the unit map, the draw pool and the drawn ids. The attempt logs go to their own folder inside `_sealed`, never the sealed folder itself. That folder must hold no .eval file at a fresh start, must not be the plumbing check's log folder, and must not equal, contain or sit inside the worker log folder. The attempt logs, the provider's Batch files and the ledger hold per-record content and are never opened before the freeze. Only pooled counts, hashes and file names are printed. Sealed files are written all or nothing and never overwritten, and the SHA-256 of each is recorded in the committed evidence. The unit map, the draw pool and the drawn ids are published after the freeze, so the draw can be checked.
  - **reply of record:** the reply of record of a unit, for each judge, is its first completed call in any attempt log, parsed or not, whatever that log's final status. A completed call has no error, is not pending and has a completed time. A unit completed in two attempt logs is refused. A resume asks only units with no reply of record, for grader and calibrator alike, and a failed judgment counts as a reply of record. Outputs of a dead Batch that no log recorded are never fetched and count as missing. A dead Batch is recovered by resume, never by retrying the eval. A batch older than 25 hours is flagged on screen, since a batch that expired with no result file is polled forever; the job is then stopped and resumed.
  - **rejected logs:** every attempt log is checked as soon as its eval ends. A log that fails its check, or that cannot be read, stops the job. Its SHA-256 is recorded in the ledger as rejected, its replies stay unused, and the author rules by a logged deviation. A resume refuses while the ledger records a rejected log. Resume is tied to HEAD on purpose: the ledger's provenance holds the commit, so a code fix after a rejection is refused as well, and the way forward is the author's logged ruling. On resume, an attempt log of this job that the ledger missed is admitted when it passes its check. One that fails its check, asks units outside its part, or cannot be read is recorded as rejected. A log of another job in the folder is refused. Until a grader attempt log with status success has been admitted, the first 12 units of grader part 1 still missing a reply and not due for their final ask (the lowest such ids) are asked as their own small eval, a rehearsal, before the rest of the part, so a broken setup costs 12 calls rather than a part. A resume after a rehearsal that did not succeed therefore rehearses again; once a grader log has succeeded, no resume rehearses. On a live run, the rehearsal's resolved model strings are checked against the pin at once; a string outside the pin is a vendor-change event that stops the job for the author's logged ruling. That stop blocks a resume like a rejected log: a resume refuses while the ledger records it. On resume, after any missed logs are admitted and before any new eval, the resolved model strings of every re-admitted attempt log are checked again, and a string outside the pin stops the job the same way. The rehearsal is disclosed in DEVIATIONS.md.
  - **ledger:** the attempt ledger sits under the git common directory, outside the working tree. It records the provenance, the seeds, the seed rule, the exact sampling calls, the Python version, every attempt with its --grader-max-samples value and, for a resume, whether --allow-final-ask was passed, the SHA-256 and kind of every attempt log, every Batch id, every failure, every rejected log and, at the end, the evidence body, so a lost evidence file can be written again. Batch ids are saved to the ledger the moment Batch accepts them, not when the eval returns, and Batch failure lines are saved as failures. A lock file beside the ledger allows one live process per ledger. A hard kill leaves the lock in place, and the author removes a stale lock. The machine is kept awake, with update restarts stopped, for the whole run.
  - **start checks:** this ruling is recorded in the same commit as the job code, its unit tests and the DEVIATIONS rows. That commit is pushed to the public remote and archived on the Wayback Machine before the first live grader or calibrator call, the plumbing check included, and the archive URL and date go in `docs/evidence/grading/`. The job refuses to start unless HEAD is clean and an ancestor of the local origin/main ref, the package is unchanged since the run commit, the step 2 look file reads PASS, and no guarded path has changed since the archived commit. The guarded paths are `scripts`, `tests`, `icfr_agent_evals`, `DEVIATIONS.md`, `docs/DECISIONS.md` and `PRE-REGISTRATION-PHASE-1.md`. The job records HEAD in the ledger and the evidence file. The plan-only run prints the four worker-log SHA-256s in hash order and the three plan-file SHA-256s; the author adds them to the archive record as worker_log_shas and plan_file_shas before the first live call, and the job then refuses any other logs or plan. A fresh start refuses when a result file or the evidence file already exists. The author's own checks before the paid run: compare the organisation's Batch queue limit for the grader model with --grader-max-samples times the mean prompt tokens per unit, which the plan-only run prints; and set the OpenAI project budget for the grader and the Anthropic Console spend limit for the calibrator for the run.
  - **unseal step:** sealed results will be opened only through a later unseal-and-report step, which is not built yet. It will refuse unless both run-report freeze checks pass, the committed grading evidence names exactly the frozen manifest's worker logs (file name, SHA-256 and eval id), and every sealed file matches its recorded SHA-256. It will then recompute the gate, the breaker, the means and the queue from the sealed per-record grades with the committed code, refuse on any mismatch, and give the run report the judge-gate results, the disagreement rate and the resolution rate. Built on 2026-11-24 as `scripts/unseal_report.py` (DEVIATIONS.md, 2026-11-24).
  - **header step:** the worker log headers record grader_step 1 while the grader of record is step 2. This is disclosed in DEVIATIONS.md. The run report will disclose it too, and will cross-check the grading logs' step 2 against the look file.
  - **build rules:** these rules were added while the code was built or reviewed, before any output, and are stated in the items above: the "|bootstrap" seed suffix and the bootstrap on complete pairs only (reliability gate); an undefined breaker rate does not trip (circuit breaker); the archive gate's guarded paths, the hashes in the archive record, and the refusal at a fresh start when a result or evidence file exists (start checks); a passed plumbing check before any part (plumbing check); the orphan-log rule, under which a log of this job that the ledger missed is admitted on resume and another job's log is refused (rejected logs); the log folder rules (sealed folder); one live process per ledger, by a lock file (ledger); continue_on_fail with --grader-max-samples, default 200, recorded per attempt (grading order); the warning before a final ask, the final ask guard and the --allow-final-ask flag (failed judgments); grader-wrong and the ambiguous disposition only, for a grader reply that did not parse with no calibrator score (queue); and the rehearsal until a grader log succeeds, the resolved-string stop that blocks a resume, and the resolved-string check on resume (rejected logs).
